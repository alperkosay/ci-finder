A Finder for the web.

One component gives your React app a file manager that feels as fast and keyboard-friendly as the one on your desktop.

Try it full screen Read the docs
This is not a screenshot. Drag files, right-click, press Space.

There is no server behind it: the @thefinder/core engine itself runs on this page, with a driver that keeps files in memory. Reload and everything starts over.

theFinder is a React component, a CSS file and a single API endpoint. The interface depends on no UI library. The server side is built on the web-standard Request → Response, so the same code runs on Next.js, Bun, Node, Express, Fastify, Koa and Hono. Files live on local disk, in S3, or both. Runtime dependencies of the core: zero.

Whatever your backend is.

The engine is one function: finder.handler(request) takes a Request and returns a Response. Bun, Hono and Next.js use it as is; Express, Fastify and Koa get thin adapters.

Uploads arrive in chunks and the server keeps no state between them. No body-size limits to hit, and it works on serverless too.

app/api/files/route.ts

import {
  createTheFinder, createNextRoutes, localDriver, uploadsDir,
} from "@thefinder/next";

const finder = createTheFinder({
  volumes: [{
    id: "uploads",
    driver: localDriver({ root: uploadsDir() }),
    url: "/uploads",
  }],
});

export const runtime = "nodejs";
export const { GET, POST } = createNextRoutes(finder);

server.ts

const driver = localDriver({ root: "./uploads" });
const finder = createTheFinder({
  volumes: [{ id: "files", driver, url: "/uploads" }],
});

Bun.serve({
  routes: {
    "/api/files": finder.handler,
    "/uploads/*": createFileServer({ driver, prefix: "/uploads" }),
  },
});

server.mjs

import { toExpress } from "@thefinder/core/node";

app.all("/api/files", toExpress(finder.handler));
app.get("/uploads/*", toExpress(
  createFileServer({ driver, prefix: "/uploads" }),
));

// Fine even if express.json() ran first:
// the adapter rebuilds the consumed body.

server.ts

import { toFastify } from "@thefinder/core/node";

fastify.register(toFastify(finder.handler), { prefix: "/api/files" });

// The plugin turns off body parsing in its own scope.

server.ts

import { toKoa } from "@thefinder/core/node";

router.all("/api/files", toKoa(finder.handler));

index.ts

// No adapter needed: Hono already uses the web-standard Request.
app.all("/api/files", (c) => finder.handler(c.req.raw));

Disk. Cloud. At the same time.

Each storage is a volume. They sit side by side in the sidebar, and you can copy and move between them.

@thefinder/core Engine auth · versions · trash · thumbnails
multipart · presigned
s3Driver S3 · R2 · MinIO Spaces · Backblaze B2
  • Write your own driver. FTP, Azure Blob, Google Drive… implementing the nine methods of the StorageDriver interface is enough.
  • The server keeps no state. The upload session travels with the client; target, permissions and extension are checked again on every chunk.
  • No database needed. Trash, versions and thumbnails live in hidden .tf-* folders inside the volume.

What's inside.

No Monaco, no CodeMirror, nothing loaded from a CDN. The editors ship in the package itself.

Code editor

Highlighting for 13 language families, find and replace, go to line, smart indent, Ctrl+S to save. The old copy goes into the version history before every save.

Markdown

Editing with a side-by-side preview. Raw HTML is not rendered and links are limited to safe schemes, so opening an untrusted file is harmless.

Image editor

Crop, rotate, flip, resize; pick the format and quality. Convert selected images to WebP or AVIF in one go.

Quick Look

Space previews images, video, audio, PDF, code and Markdown. Video seeking works through Range requests.

File picker

useFilePicker returns a Promise: adding a “Choose file” button to your form takes three lines. Outside React, openFilePicker.

CKEditor

A CKEditor 5 plugin and a CKEditor 4 connector. They do CKFinder's job: a toolbar button and uploads for pasted images.

Secure by default.

A file manager means write access to your server. theFinder has taken that seriously from day one.

Path traversal
Paths containing .. are rejected, never resolved. Symlinks pointing outside the root are hidden.
CSRF
Every request that changes something must be a POST and carry the x-thefinder header.
Archives
Zip-slip and zip-bomb protection. The total extracted size is capped.
Active content
Uploaded HTML and SVG are served with a sandbox CSP; they cannot run scripts on your site's origin.
Authorization
authorize runs before every command. 401, 403 or a per-request read-only mode.
Permissions
readOnly per volume, permission per path, extension lists and a size limit.

theFinder and elFinder.

elFinder is the first name that comes to mind for web file managers, and it has been in the field for more than fifteen years. theFinder rethinks the same job with today's stack. Both are good tools; which one suits you depends on how your project is built.

Choose theFinder if

  • your app runs on React, Next.js or a JavaScript server,
  • your files live in S3 or R2, or you run on serverless,
  • you want version history, a trash and image optimization out of the box,
  • you want the interface to match your design system through CSS variables.

Stay with elFinder if

  • your server is PHP and will stay PHP,
  • you need to connect to Dropbox, Google Drive or FTP today,
  • you work with archives like tar, 7z and rar,
  • you need ready translations beyond English and Turkish.

elFinder details are based on the documentation of the 2.1 series. If you spot a wrong or outdated row, open an issue.
